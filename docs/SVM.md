# SVM implementation and handoff

This contribution covers the from-scratch SVM, its tuning experiments, and
related plots. The final nonlinear model uses **random Fourier features (RFF)
with linear Pegasos**, an approximation to an RBF-kernel SVM. The model and feature
mapper use NumPy only. No QP solver, SMO solver, or library estimator is used.

## Prepared-data input contract

The model accepts dense, finite numeric features of shape `(n_rows, n_features)`
and one-dimensional binary labels. Training must contain exactly two classes.
All splits must use identical feature columns and ordering. NaNs, infinite
values, empty feature matrices, and mismatched sample counts are rejected.
Sparse matrices and raw text/categorical values are not supported directly.

Before calling the SVM helpers, the preprocessing and evaluation work must supply:

1. Cleaned, encoded training, validation, and test splits, with the stratified
   classification split documented.
2. Labels with `0 = standard`, `1 = premium`, derived using the training-price
   median only. Apply the same threshold to validation and test prices.
3. Features excluding price, price-derived columns such as unit/total price,
   and other leakage or identifying fields selected for removal during cleaning.
4. Features standardized using training means and standard deviations only.
   Fit imputation/encoding on training rows only as well. The SVM does not
   perform preprocessing or derive the price threshold.
5. The classification metric functions. A sweep metric must return one finite
   scalar, so select F1 from the precision/recall/F1 tuple when using that API.

An optional handoff file is `data/svm_prepared.npz` with `X_train`, `y_train`,
`X_val`, `y_val`, `X_test`, and `y_test`. The X arrays must already be scaled.
This file is a proposed exchange format, not a file generated by this module.
Keep feature names, the tier threshold, split indices, cleaning decisions, and
preprocessing statistics with the shared reproducibility artifacts.

## Fit and predict

With prepared arrays in memory:

```python
from src.svm import PegasosSVM

model = PegasosSVM(
    kernel="rff",
    lambda_=0.01,
    gamma=0.1,
    n_components=500,
    n_epochs=20,
    history_every=50_000,
    random_state=42,
)
model.fit(X_train, y_train)
labels = model.predict(X_val)
scores = model.decision_function(X_val)
```

These settings illustrate the API; they are not selected housing-data settings.
`kernel="linear"` trains directly on the supplied features. `kernel="rff"`
maps features first. The previous exact-kernel option `kernel="rbf"` has been
replaced and is rejected by the current implementation.

`classes_` stores sorted original labels. Positive scores indicate
`classes_[1]`, which is premium for 0/1 tier labels. A zero score selects that
positive class. Scores are uncalibrated decision values, not probabilities.
Use `predict` for F1/confusion matrices and `decision_function` for ROC-AUC.

| Parameter | Meaning |
|---|---|
| `lambda_` | Positive L2 regularization strength; model default `1e-4` |
| `n_iters` | Number of sampled updates when `n_epochs=None`; default 20,000 |
| `n_epochs` | Shuffled full passes; overrides `n_iters` when supplied |
| `learning_rate_power` | Exponent in `1/(lambda_ * t**power)`; default 1, allowed `(0.5, 1]` |
| `gamma` | Positive RBF parameter approximated by RFF; default 1 |
| `n_components` | Number of Fourier features, D; default 500 |
| `batch_size` | Mapping/prediction block size; default 2,048 |
| `history_every` | Full-training-loss checkpoint interval; model default 1,000 |
| `random_state` | Local random seed; default 42 |

Both model and mapper reset their parameters on fitting. Fixed seeds reproduce
the random map and sample order without changing NumPy's global RNG. Small
floating-point differences can still occur across numerical environments.

## Sweep and export

The following integration example runs once the prepared file is available and
`src.evaluate.precision_recall_f1` is implemented. It does not load or clean raw
CSV data. Equivalent calls can be included in the shared pipeline.

```python
import numpy as np

from src.evaluate import precision_recall_f1
from src.svm_experiment import save_sweep_results, sweep_svm
from src.svm_plots import plot_sweep_results

with np.load("data/svm_prepared.npz", allow_pickle=False) as data:
    X_train, y_train = data["X_train"], data["y_train"]
    X_val, y_val = data["X_val"], data["y_val"]

sweep = sweep_svm(
    X_train,
    y_train,
    X_val,
    y_val,
    metric=lambda truth, prediction: precision_recall_f1(truth, prediction)[2],
    metric_name="F1",
    lambdas=(0.001, 0.01, 0.1),
    gammas=(0.1, 1.0, 10.0),
    n_components=500,
    n_epochs=20,
    history_every=max(1, len(X_train)),
    random_state=42,
)
save_sweep_results(sweep, "results/svm")
plot_sweep_results(
    sweep,
    "report/figures",
    data_label=f"bina.az: train={sweep['n_train']}, validation={sweep['n_validation']}",
    score_as_percent=True,
)
best_model = sweep["best_model"]
```

This example records once per epoch. The sweep helper defaults to an interval
of 50,000 updates to reduce full-data checkpoint cost. Reduce the interval for
small datasets so the convergence plot has several measurements.

Sweeps use RFF and visit gamma values in supplied order, then lambda values
within each gamma. They reuse the same mapped training/validation arrays across
lambda values, retaining one gamma's arrays at a time. Each model starts from
zero. Exact score ties retain the first visited configuration.

By default, `metric(y_val, predictions)` is maximized. For score-based metrics,
set `score_input="scores"` and supply a metric accepting signed scores; the
positive class is reported in `sweep["positive_class"]`. Set
`greater_is_better=False` for metrics that should be minimized. All selection
uses validation only. The helper has no test-data input.

The return value contains `best_model`, `best_params`, `best_score`, metric
metadata, sample counts, and per-configuration `results`. Each result records
lambda, gamma, D, validation score, weight norm, margin, support count, final
objective, and history. The chosen model remains fitted on the original
training split; selection does not refit it on training plus validation.

Exports are `validation.csv` and `sweep.json`. JSON includes histories and the
chosen settings but **does not serialize the trained model or preprocessing**.
For a zero-weight model, margin width is infinite; Python's JSON export uses
`Infinity`, which strict JSON-only consumers must handle explicitly.

`n_components` is fixed within a sweep. To study the approximation dimension,
run separate sweeps with a prespecified set of D values, compare on validation
only, and plot each dimension separately.

## Recreate the figures from saved results

With `results/svm/sweep.json` produced by a real-data sweep:

```python
import json
from pathlib import Path

from src.svm_plots import plot_sweep_results

sweep = json.loads(Path("results/svm/sweep.json").read_text())
paths = plot_sweep_results(
    sweep,
    "report/figures",
    data_label="bina.az validation sweep",
    score_as_percent=True,
)
```

This only renders recorded values; it does not retrain. Use an accurate source
label and set `score_as_percent=True` only for fractional rate metrics.
The helper exports PNG and PDF versions of:

| Filename stem | Contents |
|---|---|
| `svm_convergence` | Selected model's training objective and mean hinge loss versus update |
| `svm_validation_sweeps` | Validation metric versus lambda and versus gamma, with logarithmic parameter axes |
| `svm_margin_validation` | Feature-space margin versus validation metric, with gamma/lambda encodings |

Stars identify the selected configuration. Infinite margins are omitted from
the scatter and counted in its note. No smoothing or confidence interval is
added. Connecting parameter-sweep lines are visual guides between measured
configurations. These figures do not establish cross-validation uncertainty.

## Method for the report and demo

The binary classifier minimizes

```text
J(w, b) = lambda/2 * ||w||² + mean(max(0, 1 - y_i * (wᵀ z_i + b)))
```

Here labels are -1/+1, and `z_i` is either the standardized original feature
vector or its Fourier mapping. At step t we sample an example, compute its
margin using the current parameters, and choose
`eta = 1 / (lambda * t**learning_rate_power)`. We shrink w by
`1 - eta * lambda`; if the pre-update margin is less than 1, we also add
`eta * y_i * z_i` to w and `eta * y_i` to b. The intercept is unregularized.
We then project w to the ball with radius `1/sqrt(lambda)`. Power 1 is the
classical Pegasos schedule; other allowed powers are experimental alternatives.

The Fourier mapping is

```text
phi(x) = sqrt(2/D) * cos(xW + a)
W[j,k] ~ Normal(0, 2*gamma)
a[k]   ~ Uniform(0, 2*pi)
phi(x) · phi(z) ≈ exp(-gamma * ||x-z||²)
```

The mapping is seeded and fixed during optimization and inference. Pegasos
learns only w and b. Increasing D generally reduces kernel approximation error
at greater memory and computation cost; predictive performance still needs
validation. Gamma controls how quickly the approximated similarity decreases
with squared input distance. Gamma equals `1/(2*sigma²)` under the usual RBF
length-scale parameterization.

RFF was chosen for scaling: an exact float64 training kernel for roughly
70,500 rows needs about 39.8 GB before temporary arrays. A 500-dimensional
Fourier matrix for the same rows needs about 282 MB. Mapping has O(ndD) cost,
training updates cost O(D) each, and each objective checkpoint costs O(nD).
The current implementation stores the full training Fourier matrix; batching
limits transformation temporaries and prediction memory, not that matrix's
size. Sweeps also retain the validation Fourier matrix for the current gamma.
Feature counts after encoding and the original input arrays add memory.

## Diagnostics and interpretation

- `w`, `b`: learned parameters. RFF weights correspond to cosine components,
  not original housing features. Only the linear model's weights can be
  matched directly to original feature names, with scaling considered.
- `weight_norm_`: `||w||`.
- `margin_width_`: `2/||w||`, infinite when w is zero. For RFF this is a
  distance in the mapped feature space, not meters or distance in original
  listing features. Different gamma values define different feature maps.
- `support_`: training-row indices with signed margin `<= 1 + 1e-10`, including
  points inside the margin and misclassified points. This is the assignment's
  margin-based definition, not a set of nonzero dual-QP coefficients.
- `support_vectors_`: copies of those rows in the supplied feature space
  (standardized original features when using the agreed input contract).
- `history_`: step, full-training mean hinge loss, and regularized objective,
  recorded initially, at each interval, and at the final update. Stochastic
  objectives can fluctuate; inspect the overall trajectory rather than claim
  every checkpoint decreases.
- `feature_map_`: fitted Fourier mapper for RFF, `None` for linear models.
- `n_steps_`, `n_features_in_`, `classes_`: update count, original feature
  count, and sorted label mapping.

   optimizers more directly. Baseline implementation belongs to the benchmarking
