# bina.az house prices: a decision tree and an SVM from scratch

MLE-AI-201 final project. We predict prices of real-estate listings scraped
from bina.az (Azerbaijan) with two models written **from scratch in NumPy**,
and benchmark them honestly against scikit-learn on identical data.

- **Task A, regression:** predict `log(price)`; errors are reported on the
  log scale and in AZN.
- **Task B, classification:** predict the price **tier**, premium (1) vs
  standard (0), split at the **median price of the training set**.
- **Our models:** `DecisionTree` (Gini / entropy / MSE, `src/decision_tree.py`)
  and `PegasosSVM` (hinge loss, Pegasos sub-gradient solver, linear kernel
  or random Fourier features for an RBF kernel, `src/svm.py`). No
  scikit-learn code is used inside either model.
- **Benchmark:** each of our models against matched scikit-learn baselines
  (`DecisionTreeRegressor/Classifier`, `SGDClassifier` with hinge loss,
  `SVC`), with 5-fold cross-validation, a held-out test set, timing and a
  scaling study, followed by an error analysis.

Headline test results (full run): our Task A tree reaches R² 0.870 on log
price; on Task B our Gini tree gets F1 0.926 / ROC-AUC 0.971 and our linear
Pegasos SVM F1 0.904 / ROC-AUC 0.962, each within 0.002 F1 of its best
scikit-learn counterpart. Details: `report/tables/results_headline.tex` and
`results/error_analysis.md`.

## How to run

From the repository root, with the virtual environment active:

```bash
python -m src.run_all            # everything: 12.8 minutes measured (see below)
python -m src.run_all --quick    # smoke test on subsamples: about 2 minutes
python -m pytest                 # the test suite (74 tests, about 10 seconds)
```

`run_all` runs five stages in order and passes `--quick` to each of them:

| Stage | Script | Full run (measured) |
|---|---|---|
| 1. EDA of the training split | `src/eda.py` | 3 s |
| 2. SVM tuning (train -> validation) and stability check | `src/svm_tuning.py` | 97 s |
| 3. tree tuning (train -> validation, 16,000-row subsample) | `src/tree_experiment.py` | 213 s |
| 4. benchmark vs scikit-learn | `src/benchmark.py` | 444 s (7.4 min) |
| 5. results tables, figures, error analysis | `src/analysis.py` | 8 s |
| **total** | `src/run_all.py` | **765 s (12.8 min)** |

Measured on an Apple M4 Mac (macOS 26.6). Each stage can also be run on its
own (`python -m src.eda`, `python -m src.svm_tuning`, `python -m
src.tree_experiment`, `python -m src.benchmark`, `python -m src.analysis`,
each with `--quick`); the analysis
reads the benchmark's outputs, so run the benchmark first.
`python -m src.benchmark --figures-only` redraws the scaling figure from the
saved results without refitting.

A full run writes to `results/`, `report/figures/` and `report/tables/`.
`--quick` writes everything under `results/quick/` and never overwrites the
report's numbers. Figures and everything in `results/` are gitignored: they
are regenerated by `run_all`.

## Methodology notes

- **Seeds.** `SEED = 42` (`src/data_prep.py`) is used for the split, every
  subsample, the CV folds, both of our models, and every scikit-learn
  estimator. Re-running gives the same numbers on the same platform; tiny
  floating-point differences are possible across machines.
- **Features.** `data_prep.make_features` encodes the five single-valued
  flag columns (`repair`, `mortgage`, `bill_of_sale`, `vip`, `featured`) as
  0/1 presence indicators and one-hot encodes the other text columns: 171
  features in all.
- **Split.** 70% train / 15% validation / 15% test, seeded and stratified,
  from one function every stage uses: `src/splits.py`, `get_splits`
  (`tests/test_splits.py` checks that eda, svm_tuning, benchmark and
  analysis all use it). The stratification label is the tier computed from
  the median of **all** prices; it only balances the premium share across
  the splits (50.3% in each) and no model sees it.
- **No test data in any model choice.** The tier labels the models use come
  from the **median of the training prices** (215,000 AZN); validation and
  test are labelled with that same threshold. Standardization (for the SVMs)
  uses **training means and standard deviations only**. Hyperparameters are
  chosen on the **validation** split. The test split is used once, for the
  final numbers.
- **SVM tuning** (`src/svm_tuning.py`). Grid: λ ∈ {1e-7, …, 1e-1} for the
  linear and the RFF kernel; for RFF, γ ∈ {0.1, 1, 10} × 1/n_features with
  500 random features; 20 epochs. Selection metric: validation F1.
  **Selection rule:** for each kernel, among configurations within 0.005
  validation F1 of the best, take the **largest λ**, because Pegasos needs
  many more updates than 1/λ to converge (step size 1/(λt)). A stability
  check re-scores each kernel's max-F1 and chosen configs with the
  benchmark's 5-fold CV (`results/svm_tuning/stability_check.csv`). Linear:
  λ = 1e-3 either way, CV F1 0.897 ± 0.003. RFF: λ = 1e-6, γ = 0.1 × scale
  either way (no larger λ was within 0.005), CV F1 0.763 ± 0.095: it needs
  10^6 updates but a 16,000-row fold gives 320,000. The **final SVM** is the
  kernel whose chosen configuration has the higher validation F1: linear,
  λ = 1e-3.
- **Tree tuning** (`src/tree_experiment.py`). Our tree only, fit on a
  stratified 16,000-row training subsample (5,000 with `--quick`) and scored
  on the validation split; the test split is not used. Step 1: max_depth ∈
  {2, 4, …, 12} with min_samples_leaf 1 (Task B for Gini and entropy); step
  2: min_samples_leaf ∈ {1, 5, 20, 50} at the chosen depth;
  min_samples_split is 10. **Selection rule:** in each step, the best
  validation score (Task A RMSE of log price, Task B F1), then among configs
  within 0.002 of it the smallest max_depth (step 1) or the largest
  min_samples_leaf (step 2). Chosen: Task A depth 12, leaf 5; Task B depth
  10, leaf 5, with entropy as the better criterion on validation. The
  benchmark reads `results/tree_final_config.json`, fits both Task B
  criteria with that config, and caps depth at 12; the results and error
  analysis use the Gini tree as the main Task B tree.
- **Cross-validation on a 20,000-row subsample.** CV uses a stratified
  20,000-row sample of train + validation, then 5-fold `StratifiedKFold`.
  Inside each fold, the tier threshold and the scaler come from that fold's
  training rows only. The subsample keeps the run practical: our pure-Python
  tree takes about 10 s per fit at 16,000 rows but about 86 s at 63,919,
  and CV fits three trees per fold.
- **SVC capped at 10,000 rows.** Exact-kernel `SVC` grows roughly
  quadratically with the number of rows, so it is fit on at most 10,000
  stratified training rows, with C = 1/(n · λ), n being the rows SVC
  actually sees (this makes its objective a rescaling of Pegasos' at the same
  λ). Our SVMs and `SGDClassifier` use the full training split.
- **Matched baselines.** Linear Pegasos is compared with `SGDClassifier(hinge,
  l2, alpha = λ)` and `SVC(kernel="linear")`; RFF Pegasos with the same
  random-Fourier construction (`RBFSampler`) + `SGDClassifier`, and with
  `SVC(kernel="rbf")` at the same γ. Trees are compared with scikit-learn
  trees at the same depth and minimum-sample settings.
